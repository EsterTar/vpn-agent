# Исследование протоколов для VPN-сервиса (РФ, март 2026)

> Дата исследования: 15 марта 2026
> Статус: ситуация меняется еженедельно, требуется регулярная ревалидация

---

## TL;DR

- **Голые** Shadowsocks, VLESS+Reality, OpenVPN, WireGuard — **не работают** надёжно в РФ
- **Работает:** VLESS + XHTTP + Reality, Hysteria2 + Salamander
- **Ключевой принцип:** устойчивость не в протоколе, а в комбинации технологий (протокол + транспорт + обфускация)
- **Архитектурно:** система должна позволять быстро менять транспорт без переконфигурации клиентов

---

## 1. Как работает ТСПУ (система блокировок)

ТСПУ — не один фильтр, а несколько последовательных слоёв проверки, каждый дороже по вычислениям.

| Слой | Что анализирует | Что ловит |
|------|-----------------|-----------|
| 1. Magic bytes | Первые 16-32 байт пакета | OpenVPN, WireGuard, голый Shadowsocks |
| 2. TLS fingerprinting (JA3) | Хеш параметров TLS ClientHello | Нестандартные TLS-клиенты, устаревшие библиотеки |
| 3. IP/ASN mismatch | Несоответствие SNI и реального IP | Reality с sni=google.com на IP Hetzner |
| 4. Поведенческий анализ (ML) | Паттерны пакетов, timing, объём | Длительные туннели, нетипичные для заявленного SNI |

### Работают

| Связка | Почему работает | Ограничения | Источники |
|--------|----------------|-------------|-----------|
| **VLESS + XHTTP + Reality** | XHTTP разделяет upstream/downstream в отдельные HTTP-транзакции, ломая поведенческие паттерны, которые детектирует ТСПУ | Протокол новый — нет гарантии долгосрочной устойчивости. Версии Xray на клиенте и сервере должны совпадать | [Habr](https://habr.com/ru/articles/1009542/), [GitHub](https://github.com/ServerTechnologies/3x-ui-with-xhttp) |
| **Hysteria2 + Salamander** | UDP/QUIC-based. Salamander обфусцирует на уровне Initial-пакетов, ломая QUIC-детекцию ТСПУ до её срабатывания | Некоторые провайдеры режут UDP на порту 443 или throttle'ят QUIC целиком | [Habr](https://habr.com/ru/articles/1008554/) |
| **VLESS + gRPC/WS через Cloudflare CDN** | Трафик идёт через CF — блокировка CF = коллатеральный ущерб для легитимных сервисов | **CF обновил ToS (декабрь 2024):** proxy/VPN-сервисы через их сеть запрещены. Риск бана аккаунта. Использовать только как аварийный fallback | [Cloudflare Community](https://community.cloudflare.com/t/confusion-about-tos-in-relation-to-using-cloudflared-tunnel-for-media-streaming/839900) |

## 3. Выбранный стек

```
Основной:     VLESS + XHTTP + Reality (Xray-core v26.2+, порт 443)
Fallback:     Hysteria2 + Salamander (UDP)
Аварийный:    VLESS + WS/gRPC через Cloudflare CDN (учитывая ToS-риск)
Панель:       3X-UI (управление ключами, expiry, лимиты трафика, subscription links)
```

### Почему этот стек

1. **VLESS + XHTTP** — наиболее устойчив к текущей версии ТСПУ по консенсусу ntc.party и Habr
2. **Hysteria2** — другой принцип (UDP vs TCP), работает когда TCP-based решения под ударом
3. **3X-UI** — поддерживает оба протокола, multi-user, expiry ключей, лимиты, subscription links для автообновления конфигов на клиентах
4. **Subscription link** — критически важен: позволяет менять транспорт на сервере, а клиенты подхватывают новый конфиг автоматически

### Клиенты (что ставят пользователи)

| Платформа | Клиент | Поддержка XHTTP | Поддержка Hysteria2 |
|-----------|--------|-----------------|---------------------|
| Android | v2rayNG | Да | Да |
| iOS | Streisand, V2Box | Да | Да |
| Windows | v2rayN, Nekoray | Да | Да |
| macOS | V2Box, Nekoray | Да | Да |

## 4. VPS — где размещать сервер

| Провайдер | Локация | Цена/мес | Пинг до Москвы | Примечания |
|-----------|---------|----------|----------------|------------|
| **Hetzner** | Амстердам, Франкфурт | ~€4-5 | 20-35мс | Безлимит, Anti-DDoS. Но IP Hetzner уже в базах ТСПУ как "хостинг" — повышенная подозрительность |
| **Vultr** | Амстердам, Стокгольм | ~$5-6 | 25-40мс | Безлимит (fair use ~10ТБ) |
| **DigitalOcean** | Амстердам | ~$6 | 25-35мс | Безлимит (fair use) |

**Минимальные требования:** 1 vCPU, 512MB-1GB RAM, 10GB SSD, канал 100+ Мбит/с.

**Важно:** один IP = одна точка отказа. Если ТСПУ заблокирует IP — все клиенты лежат.

## 5. Подводные камни и риски

### Технические

| Риск | Импакт | Митигация |
|------|--------|-----------|
| ТСПУ адаптируется к XHTTP | Полная блокировка основного канала | Fallback на Hysteria2 + подписочная ссылка для быстрой смены конфига |
| Блокировка IP VPS | Все клиенты лежат | Несколько VPS или CDN-прослойка (с учётом ToS-рисков) |
| UDP режется провайдером | Hysteria2 не работает | Не у всех провайдеров; основной канал — TCP |
| Версии Xray не совпадают | XHTTP молча не работает | Фиксировать версии, тестировать обновления |
| Региональные различия | Работает в Москве, не работает в Краснодаре | Мониторинг от пользователей, несколько конфигураций |

### Бизнесовые

| Риск | Импакт | Митигация |
|------|--------|-----------|
| CF бан за нарушение ToS | Потеря аварийного fallback | Использовать только как крайний вариант, не основной |
| Быстрое устаревание протоколов | Нужно постоянно обновлять стек | Subscription links + архитектура, позволяющая менять транспорт без участия клиента |
| Правовые риски | Организация VPN-сервиса в юрисдикции, связанной с РФ | Отдельное исследование, выходит за рамки технического анализа |
